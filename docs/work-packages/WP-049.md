# WP-049 - Bancas canónicas Q3/Recinto y ciclo visual único

## Estado documental

`APROBADO`

## Objetivo

Eliminar definitivamente las divergencias entre las bancas de Q3 y las de la Pantalla del Recinto, unificando semántica, ciclo temporal y geometría verificable sin comprometer el secreto de voto.

## Resultado esperado

Para un mismo snapshot y un mismo instante visual, Q3 y Recinto presentan el mismo estado de cada banca: presencia, uso de palabra, test, participación `Voto emitido` y resultado final. Los resultados individuales se retiran en ambas superficies al vencer la misma frontera temporal.

Dentro de cada superficie todas las tarjetas tienen dimensiones uniformes, filas realmente centradas, imagen completa y una única etiqueta máxima.

## Decisiones humanas cerradas

1. Q3 y Recinto deben comportarse igual respecto del estado visual de cada concejal.
2. Durante votación en curso, una banca que ya votó muestra `Voto emitido` en ambas superficies sin revelar sentido.
3. Después del cierre, ambas superficies muestran el sentido final por el mismo período y luego retiran colores/etiquetas de resultado.
4. La implementación debe investigar primero por qué la prueba humana observó `Voto emitido` en Recinto pero no en Q3, dado que el código integrado aparentemente ya transporta la señal.
5. Si el problema no se reproduce en el SHA exacto de main, no se inventa un parche: se fortalece la prueba E2E y se documenta la causa runtime/build si puede demostrarse.
6. Todas las tarjetas dentro de una misma superficie tienen exactamente el mismo ancho y alto.
7. Cada tarjeta contiene visualmente solo:
   - imagen institucional completa;
   - como máximo una etiqueta de estado.
8. La etiqueta puede representar `Ausente`, `En uso de la palabra`, `Voto emitido` o resultado final; test puede continuar sin texto.
9. Imagen y etiqueta se centran horizontalmente.
10. Las filas de bancas deben estar realmente centradas en el área disponible, incluso cuando la diferencia entre cantidad máxima y cantidad de una fila sea impar.
11. Las imágenes no pueden quedar recortadas; si hace falta se reduce su escala y se aumenta la altura útil de la tarjeta.
12. Q3 puede conservar menor escala global que Recinto; la uniformidad exigida es dentro de cada superficie y la semántica/temporalidad sí es idéntica entre ambas.

## Alcance

### 1. Diagnóstico obligatorio de `Voto emitido`

Antes de modificar comportamiento:

1. partir del SHA exacto de `origin/main`;
2. ejecutar el stack integrado;
3. abrir una votación;
4. emitir votos parciales;
5. observar simultáneamente Q3 y Recinto;
6. inspeccionar DTOs adoptados y DOM;
7. determinar si la divergencia es de backend, proyección, api-client, frontend, build/runtime o no reproducible.

La PR debe documentar el resultado.

### 2. Frontera temporal única del resultado

Q3 no debe derivar una política temporal propia con un número mágico.

La solución debe exponer o reutilizar una frontera autoritativa común equivalente a `resultado_visible_hasta` para que Q3 y Recinto sepan cuándo dejar de presentar el resultado individual.

Se autoriza, si es necesario para corregir la capa adecuada:

- ampliar `VotacionModeracion` con un deadline de presentación calculado por backend;
- factorizar el cálculo para que Moderación y Recinto usen exactamente la misma semántica;
- actualizar OpenAPI y api-client.

La votación/resultados siguen existiendo en Moderación después de esa frontera para Q1 y lógica operativa; lo que expira es la **presentación de resultado en las tarjetas de Q3**, no el estado institucional.

### 3. Semántica canónica

Conservar `calcularPresentacionBanca` como autoridad compartida o reemplazarla por una abstracción común equivalente, manteniendo una única prioridad.

Orden vigente a preservar salvo contradicción canónica:

1. resultado final visible;
2. Voto emitido durante EN_CURSO;
3. test;
4. uso de palabra;
5. ausencia;
6. normal.

Secreto:

- durante EN_CURSO nunca aparece sentido individual;
- `Voto emitido` solo informa participación;
- no se exponen DNI, teclas ni timestamps individuales.

### 4. Geometría uniforme

Q3 y Recinto deben cumplir:

- mismo ancho y alto para todas las tarjetas de esa superficie;
- dimensiones independientes del nombre, imagen, estado o etiqueta;
- área de imagen con `object-fit: contain` o equivalente sin recorte;
- imagen centrada horizontal y verticalmente;
- una única franja/etiqueta máxima;
- etiqueta centrada;
- reserva geométrica estable aunque no haya etiqueta;
- sin texto duplicado de nombre/apellido/banca fuera del bitmap, salvo fallback accesible ante imagen fallida;
- sin scroll dentro de la tarjeta.

### 5. Centrado real de filas

Corregir el algoritmo/layout que actualmente usa columnas enteras y puede sesgar una fila cuando el sobrante es impar.

El centrado se valida geométricamente:

- centro horizontal del conjunto de tarjetas de cada fila ≈ centro horizontal del área de bancas;
- tolerancia E2E pequeña y explícita;
- no basta con verificar clases CSS o una inspección visual.

### 6. Altura útil de tarjetas

Aumentar la proporción vertical disponible a las bancas sin introducir scroll global ni recortar otras áreas obligatorias.

Las imágenes pueden ocupar un porcentaje menor de la tarjeta si eso permite preservar el bitmap completo y la etiqueta.

## Criterios de aceptación

1. El diagnóstico de `Voto emitido` queda reproducido y corregido, o documentado como no reproducible con evidencia del SHA/runtime y un E2E que lo cubre.
2. Durante EN_CURSO una banca que ya votó muestra `Voto emitido` en Q3 y Recinto.
3. Durante EN_CURSO ninguna de las dos superficies revela POSITIVO/NEGATIVO/ABSTENCION.
4. Tras el cierre ambas superficies muestran el mismo resultado individual.
5. Al vencer la misma frontera temporal ambas retiran resultado/color/etiqueta individual.
6. Q1 puede continuar conservando el resultado operativo previo; la expiración visual de Q3 no borra estado institucional.
7. Para un mismo estado lógico, Q3 y Recinto obtienen igual `data-estado-banca`/semántica.
8. Todas las tarjetas de Q3 tienen ancho y alto iguales entre sí.
9. Todas las tarjetas de Recinto tienen ancho y alto iguales entre sí.
10. Cambiar de NORMAL a AUSENTE/PALABRA/VOTO_EMITIDO/RESULTADO no cambia dimensiones.
11. Cada tarjeta dibuja como máximo una etiqueta.
12. No se dibujan nombre/apellido/banca duplicados fuera de la imagen en condiciones normales.
13. Imagen completa visible, sin clipping.
14. Imagen y etiqueta centradas horizontalmente.
15. Cada fila queda centrada respecto del área de bancas, incluida una geometría con diferencia impar entre filas.
16. No aparece scroll global a 1366×768 ni 1920×1080.
17. Q3 no genera scroll propio para las bancas.
18. Si se modifica contrato, OpenAPI y api-client quedan sin drift.
19. Sin nuevas dependencias.

## Pruebas obligatorias

### Backend/contrato, si aplica

- deadline de resultado equivalente en Moderación/Recinto;
- resultado institucional no desaparece de EstadoModeracion;
- `bancas_voto_emitido` solo expone participación durante EN_CURSO;
- OpenAPI/api-client sincronizados.

### Frontend

- tabla exhaustiva de estados de `calcularPresentacionBanca`;
- Q3 y Recinto con las mismas entradas producen mismo estado/etiqueta/familia;
- expiración temporal de resultado en Q3;
- Voto emitido simultáneo;
- cambio de estado no altera estructura interna.

### Playwright integrado

A 1366×768 y 1920×1080:

- voto parcial: misma banca = `Voto emitido` en Q3 y Recinto;
- cierre: sentidos visibles iguales;
- esperar frontera: colores/etiquetas de resultado desaparecen en ambas;
- ausencia, palabra y test;
- medir ancho/alto de todas las tarjetas;
- medir centros horizontales de cada fila;
- comprobar imagen no recortada y sin scroll global.
