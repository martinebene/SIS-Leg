# WP-031 - Lanzamiento de agentes sin prompt automático y salida copiable de OpenCode en Orca

## Estado documental

`APROBADO`

## Objetivo

Separar explícitamente las responsabilidades del launcher y del orquestador: los scripts de inicio deben limitarse a validar el estado operativo, sincronizar el repositorio, crear o reutilizar correctamente el worktree/rama y abrir el agente asignado; el prompt exhaustivo debe ser redactado por ChatGPT Web/orquestador, mostrado al operador en la interfaz y trasladado manualmente por el operador al agente.

Además, cuando el entorno operativo sea Orca y el agente efectivo sea OpenCode, el prompt debe incluir una instrucción específica para espejar únicamente la respuesta final de ese turno en una terminal común del mismo worktree, de modo que pueda copiarse con fiabilidad desde clientes donde la TUI de OpenCode dificulta el copiado, especialmente en móvil.

## Resultado esperado

El flujo Orca debe poder iniciar un WP autorizado y abrir el agente correspondiente sin enviarle automáticamente ningún prompt de trabajo.

El operador recibe el prompt exhaustivo directamente de ChatGPT Web, puede leerlo/revisarlo y lo copia/pega manualmente en la sesión del agente abierta por Orca.

El launcher Orca debe retirar completamente `construir_prompt_inicial()` y dejar de agregar `--prompt` al comando normal de creación. Después de abrir correctamente el agente debe imprimir una indicación breve, sin contenido de trabajo, equivalente a:

```text
Agente abierto. Pegá ahora el prompt entregado por el orquestador.
```

Si el agente abierto es OpenCode y se está trabajando bajo Orca, el prompt redactado por el orquestador incluye un bloque condicional de salida copiable: al finalizar el turno, OpenCode prepara su respuesta final, guarda exactamente ese texto en un archivo temporal fuera del repositorio y utiliza la skill `orca-cli` para crear una terminal común del mismo worktree cuyo único contenido relevante sea el `cat` de esa respuesta.

El lanzador genérico conserva el mismo principio de separación de responsabilidades para el inicio del agente, pero la función de salida copiable de OpenCode **no aplica fuera de Orca**.

## Decisiones operativas aprobadas

### 1. El launcher no transporta el prompt

La separación queda así:

1. ChatGPT Web/orquestador reconstruye el estado real, planifica el WP y redacta el prompt exhaustivo específico.
2. El launcher realiza únicamente trabajo mecánico y verificable de entorno/Git/Orca.
3. El launcher abre el agente asignado sin prompt inicial de trabajo.
4. ChatGPT Web muestra el prompt completo al operador.
5. El operador puede leerlo/revisarlo antes de copiarlo/pegarlo manualmente en el agente.
6. El agente ejecuta ese prompt dentro del worktree preparado.

La revisión humana visible del prompt forma parte deliberada del flujo y no se considera una fricción a automatizar.

### 2. `construir_prompt_inicial()` se elimina completamente

No debe conservarse como compatibilidad interna ni código muerto. El launcher Orca no genera, interpreta, valida, almacena ni transporta texto de trabajo para el agente.

El comando normal de `orca worktree create` conserva `--agent` pero no utiliza `--prompt`.

### 3. El launcher imprime solo una indicación breve al finalizar

Una vez que Orca haya creado/verificado correctamente el worktree y abierto el agente, el launcher debe informar al operador que el siguiente paso es pegar el prompt entregado por ChatGPT Web.

El mensaje no debe contener ni reconstruir el prompt ni introducir instrucciones de implementación adicionales.

### 4. La salida copiable aplica solo a OpenCode bajo Orca

La función de espejo de salida se aplica únicamente cuando se cumplen simultáneamente ambas condiciones:

- entorno operativo: Orca;
- agente efectivo: OpenCode.

No se intenta reproducir este comportamiento en terminal/SSH/Warp u otros entornos genéricos, ni se impone a AGY, Codex, Claude u otros agentes.

### 5. No se exporta ni parsea la sesión completa de OpenCode

No se usa `opencode export` como fuente de la salida a copiar. Se evita depender de reconstruir el historial o distinguir mensajes previos dentro de una exportación completa.

El procedimiento aprobado es:

1. OpenCode compone primero la respuesta final que va a devolver al operador/orquestador.
2. Antes de emitirla en la TUI, guarda **exactamente ese texto final** en un archivo temporal fuera del repositorio.
3. Carga/usa la skill `orca-cli` y crea una terminal común del mismo worktree mediante la CLI oficial de Orca.
4. Esa terminal ejecuta un comando equivalente a `cat <archivo-temporal>`.
5. OpenCode emite después en su TUI el mismo texto que fue espejado.

El orden es obligatorio porque el agente no puede ejecutar herramientas después de haber terminado su respuesta final. Al concluir el turno queda disponible una pestaña de terminal común con exactamente la salida que el operador necesita copiar.

## Bootstrap excepcional de WP-031

WP-031 modifica precisamente el launcher Orca integrado que, antes de este WP, todavía agrega un prompt automático mediante `--prompt`. Por esa dependencia circular, usar `scripts/iniciar_wp_orca.py` para iniciar WP-031 haría que el propio arranque incumpla la separación aprobada en este documento.

Por única vez para WP-031 se autoriza el siguiente bootstrap:

1. el WP debe estar `APROBADO` y `PLAN.md` debe marcarlo `EN_CURSO` con un único agente asignado;
2. el checkout coordinador debe estar en `main`, limpio y sincronizado por fast-forward con `origin/main`;
3. deben verificarse runtime Orca listo, repositorio registrado, dependencia WP-030 `INTEGRADO` y ausencia de colisiones Git/Orca para WP-031;
4. el worktree se crea directamente con `orca worktree create`, usando `origin/main`, `--no-parent`, `--agent <agente>`, setup normal y activación, **sin `--prompt`**;
5. la respuesta JSON de Orca debe demostrar worktree/rama válidos, HEAD inicial idéntico al `origin/main` validado, `baseRef` correspondiente a `origin/main`, ausencia de padre y terminal del agente efectivamente iniciada;
6. el prompt exhaustivo se entrega después al operador en ChatGPT Web para copia/pegado manual.

Esta excepción no habilita a omitir ninguna puerta del launcher ni crea una alternativa permanente. Una vez integrado WP-031, el inicio normal de los WPs bajo Orca vuelve a realizarse mediante `scripts/iniciar_wp_orca.py` ya corregido.

## Contrato de salida copiable OpenCode + Orca

Cuando corresponda, el prompt escrito por ChatGPT Web debe incluir al final un bloque operativo equivalente a estas reglas:

- cargar la skill `orca-cli` antes de usar la CLI de Orca y no inventar flags de memoria;
- trabajar sobre el worktree actual, identificado de forma inequívoca;
- construir primero el informe/respuesta final completo;
- guardar únicamente ese texto en un archivo temporal no versionado y fuera del árbol Git;
- usar un nombre predecible por WP, por ejemplo `/tmp/sis-leg-wp-NNN-opencode-ultima-respuesta.txt`, sobrescribiéndolo para que represente siempre la última respuesta de ese WP;
- abrir una terminal común del mismo worktree con `orca terminal create`, usando un selector explícito válido del worktree y un título identificable como `Salida OpenCode WP-NNN`;
- ejecutar en esa terminal únicamente un comando de lectura del archivo, equivalente a `cat`, sin iniciar otro agente;
- no incluir prompt del usuario, historial anterior, razonamiento interno, tool calls ni logs en el archivo espejado;
- el contenido espejado debe coincidir con la respuesta final visible de OpenCode;
- no modificar archivos versionados ni el estado Git para realizar este espejo;
- si Orca/skill/terminal no están disponibles, no improvisar otra automatización: conservar el archivo temporal si fue posible y reportar el fallo operativo de forma explícita.

La terminal adicional es una ayuda de interfaz/copia. No constituye una segunda sesión de agente ni viola la regla de revisión secuencial del worktree.

## Problema a resolver

El launcher Orca integrado actualmente contiene `construir_prompt_inicial()` y agrega `--prompt <texto>` a `orca worktree create`. Ese prompt es breve y puede hacer que el agente empiece antes de recibir la instrucción exhaustiva real.

Por otra parte, la TUI de OpenCode presenta dificultades de copiado en algunos clientes móviles. Orca ofrece terminales comunes por CLI y la skill `orca-cli`, lo que permite espejar la respuesta final sin parsear la sesión completa.

WP-031 resuelve ambos problemas sin convertir el launcher en orquestador ni transportador de prompts.

## Alcance

- Modificar `scripts/iniciar_wp_orca.py` para que `orca worktree create` abra el agente asignado sin `--prompt`.
- Eliminar completamente `construir_prompt_inicial()` y cualquier código usado exclusivamente para transportar ese prompt automático.
- Mantener `--agent <agente>` y todas las opciones/validaciones necesarias para crear el worktree, ejecutar setup, activarlo y abrir el agente.
- Hacer que el launcher imprima al finalizar una indicación breve para que el operador pegue el prompt entregado por el orquestador, sin incluir contenido de trabajo.
- Preservar las validaciones de checkout coordinador, sincronización con `origin/main`, autorización del WP, dependencias, agente asignado, runtime Orca, repositorio registrado y conflictos.
- Ajustar los tests del launcher Orca para demostrar presencia de `--agent`, ausencia de `--prompt`, ausencia de generación de prompt y presencia del aviso final.
- Mantener funcionalmente `scripts/iniciar_wp.py` sin inyección automática de prompts.
- Actualizar `PROMPTS_AGENTES.md` y `ORQUESTACION.md` para establecer el traslado manual ChatGPT Web -> operador -> agente.
- Incorporar en `PROMPTS_AGENTES.md` la regla condicional OpenCode + Orca de salida copiable definida arriba.
- Documentar como prerrequisito operacional que OpenCode debe poder cargar la skill oficial `orca-cli` cuando se pretenda usar esta función.
- Realizar una validación manual controlada en Orca que compruebe que una respuesta de prueba de OpenCode aparece en una nueva terminal común y es copiable.

## Criterios de aceptación

1. `scripts/iniciar_wp_orca.py` sigue validando checkout, limpieza y sincronización con `origin/main`.
2. Sigue validando WP aprobado, estado `EN_CURSO`, agente asignado y dependencias integradas.
3. Sigue validando runtime Orca, repositorio registrado y ausencia de conflictos.
4. `orca worktree create` mantiene `--agent` y no incluye `--prompt`.
5. `construir_prompt_inicial()` ya no existe.
6. El launcher no construye, guarda, valida ni transporta texto de trabajo.
7. Orca sigue abriendo correctamente el agente y el launcher conserva evidencia suficiente del worktree/terminal creado.
8. Tras un lanzamiento correcto, el launcher muestra una indicación breve para pegar el prompt entregado por el orquestador, sin contenido de implementación.
9. El prompt exhaustivo se entrega al operador en ChatGPT Web para copia/pegado manual.
10. El lanzador genérico conserva su comportamiento actual sin prompt automático.
11. Los tests fallan si `--prompt` o generación automática de prompts reaparecen accidentalmente.
12. Todas las regresiones de seguridad de WP-030 permanecen verdes.
13. `PROMPTS_AGENTES.md` define de forma inequívoca que el espejo de salida solo aplica a OpenCode bajo Orca.
14. El espejo contiene únicamente la respuesta final del turno y no historial, razonamiento ni salidas de herramientas.
15. El archivo temporal está fuera del repositorio y no altera `git status`.
16. La terminal adicional es una terminal común del mismo worktree creada con Orca, no otro agente.
17. Una validación manual demuestra que la respuesta espejada puede leerse/copiarse desde esa terminal.
18. Si la skill/CLI de Orca no está disponible, el agente falla de forma explícita en esta ayuda de interfaz sin inventar una alternativa insegura ni modificar el alcance funcional.
19. No se automatizan decisiones humanas, revisión ni merge.
20. El WP conserva el formato parseable de `FORMATO_WP_LANZADORES.md`.

## Pruebas obligatorias

- Test que demuestra que `construir_prompt_inicial()` fue retirado y que el launcher no genera texto de trabajo.
- Test del aviso final posterior a un lanzamiento exitoso.
- Regresión completa de `tests/test_iniciar_wp_orca.py`.
- Validaciones previas continúan fallando cerrado ante estados inválidos.
- Regresión del lanzador genérico si se toca código compartido.
- Suite completa Python.
- Puertas globales de CI vigentes al momento de implementación.
- `git diff --check`.
- Validación manual específica OpenCode + Orca + skill `orca-cli`: prompt de prueba, archivo temporal, terminal creada y contenido exacto visible/copiable.

Los tests automatizados no deben requerir un runtime Orca real; la comprobación de interfaz OpenCode + Orca es una validación manual operativa separada.

## Invariantes y restricciones

- El repositorio y la documentación canónica siguen siendo fuente de verdad.
- El prompt exhaustivo sigue siendo responsabilidad de ChatGPT Web/orquestador.
- El operador conserva una instancia humana explícita entre la redacción y ejecución del prompt.
- El launcher no interpreta ni modifica el prompt porque no lo recibe.
- El espejo OpenCode + Orca es una función de presentación de la salida, no de autorización ni de control del agente.
- Ningún launcher puede autoautorizar un WP, alterar decisiones reservadas o integrar una PR.
- Deben preservarse DEC-004, DEC-005, DEC-007 y las validaciones existentes.
- Cualquier automatización futura del transporte de prompts o captura persistente de sesiones requiere una decisión explícita nueva.

## Flujo objetivo después de WP-031

```text
ChatGPT Web / orquestador
  -> entrega comando de launcher

launcher Orca
  -> valida Git/WP/agente/Orca
  -> crea worktree/rama
  -> abre agente SIN prompt
  -> informa: pegar prompt entregado por el orquestador

ChatGPT Web / orquestador
  -> muestra prompt exhaustivo
  -> si agente=OpenCode y entorno=Orca, incluye bloque de salida copiable

operador
  -> revisa y pega el prompt

OpenCode bajo Orca
  -> ejecuta trabajo
  -> compone respuesta final
  -> la guarda fuera del repo
  -> carga/usa skill orca-cli
  -> crea terminal común del mismo worktree con cat de esa respuesta
  -> emite la misma respuesta final en OpenCode
```

## Herramientas MCP y documentación técnica externa

Aplicar DEC-003 ante comportamiento/versiones de Orca u OpenCode. Para la planificación se verificó en fuentes oficiales que:

- `--agent` y `--prompt` son opciones separadas de `orca worktree create`;
- Orca ofrece `orca terminal create` para crear una terminal dentro de un worktree;
- Orca distribuye la skill `orca-cli` para que los agentes carguen una guía compatible con la versión instalada;
- OpenCode dispone de herramienta `skill` y puede ejecutar comandos de shell.

La implementación debe volver a confirmar la sintaxis exacta contra la versión instalada antes de fijar comandos definitivos.
