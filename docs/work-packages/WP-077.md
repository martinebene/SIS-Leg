# WP-077 - Renombrar Botonera2 a SIS-Leg en repositorios y código vigente

## Estado documental

`APROBADO`

## Objetivo

Completar el cambio de identidad técnica y documental del proyecto desde el nombre legado `Botonera2` / `botonera2` hacia el nombre oficial **SIS-Leg**, incluyendo repositorios, referencias canónicas, gobernanza, comentarios de código, paquetes, módulos, artefactos operativos y metadatos actuales, sin reescribir evidencia histórica inmutable.

## Resultado esperado

Al completar el corte:

- repositorio de producto: `martinebene/SIS-Leg`;
- repositorio de control: `martinebene/SIS-Leg-Control`;
- nombre humano/oficial en documentación y UI textual: `SIS-Leg`;
- identificadores técnicos usan una normalización consistente:
  - minúsculas con guion donde sea válido: `sis-leg`;
  - identificadores Python/variables donde el guion no sea válido: `sis_leg`;
  - variables de entorno: prefijo `SIS_LEG_`;
  - paquetes npm: scope `@sis-leg`;
- no quedan referencias activas/canónicas a `Botonera2`, `Botonera2-Control`, `botonera2` o `@botonera2`, salvo evidencia histórica que deba permanecer inmutable y quede explícitamente documentada como legado.

- Marca visible/oficial: `SIS-Leg`.
- Repo producto: `martinebene/SIS-Leg`.
- Repo control: `martinebene/SIS-Leg-Control`.
- Slug técnico cuando admite guion: `sis-leg`.
- Identificador técnico cuando no admite guion: `sis_leg`.
- Scope npm: `@sis-leg`.
- Prefijo de entorno: `SIS_LEG_`.

La denominación visual del logo humano aprobado no se redibuja ni se altera en píxeles dentro de este WP. El asset gráfico conserva la protección vigente; sólo cambian referencias textuales y técnicas.

## Alcance

### 1. Repositorios y coordinación

- Preparar y ejecutar el corte de nombres:
  - `martinebene/Botonera2` -> `martinebene/SIS-Leg`;
  - `martinebene/Botonera2-Control` -> `martinebene/SIS-Leg-Control`.
- Actualizar todos los remotos canónicos después del rename.
- Actualizar `CURRENT.json`, protocolo, AGENTS y documentos vigentes del repositorio Control.
- Renombrar campos actuales de esquema que incorporen literalmente el nombre legado, con migración coordinada de cualquier parser/consumidor.
- Actualizar referencias del Product hacia el Control y viceversa.
- Verificar notificaciones, workflows, webhooks y cualquier integración que contenga el nombre completo de los repositorios.
- No confiar en redirects como configuración permanente.

### 2. Código y paquetes

- Renombrar distribución raíz `botonera2` a `sis-leg`.
- Backend:
  - distribución `botonera2-backend` -> `sis-leg-backend`;
  - módulo/imports `botonera2_backend` -> `sis_leg_backend`.
- Device Bridge:
  - distribución/CLI `botonera2-device-bridge` -> `sis-leg-device-bridge`;
  - módulo/imports `botonera2_device_bridge` -> `sis_leg_device_bridge`.
- Paquetes TypeScript/Nuxt:
  - `@botonera2/*` -> `@sis-leg/*`.
- Actualizar imports, manifests, lockfiles, build, tests y tooling.
- Renombrar nombres de archivo/directorio que formen parte de la identidad activa cuando corresponda.

### 3. Operación y despliegue

- Renombrar artefactos operativos activos:
  - archivos systemd;
  - nombres de servicios;
  - usuarios/grupos de servicio si forman parte del branding técnico;
  - paths bajo `/opt/botonera2` hacia `/opt/sis-leg`;
  - configuración nginx `botonera2.conf` hacia `sis-leg.conf`;
  - ejecutables y scripts;
  - variables de entorno `BOTONERA2_*` hacia `SIS_LEG_*`.
- Definir una migración segura de una instalación existente:
  - backup;
  - detener servicios en orden;
  - migrar rutas/config preservando archivos runtime;
  - actualizar unidades;
  - daemon-reload;
  - levantar y verificar;
  - rollback documentado.
- No perder configuración local/runtime introducida por WP-073.

### 4. Documentación, gobierno y comentarios

- Reemplazar el nombre legado en:
  - README;
  - manual;
  - docs de arquitectura, reglas, despliegue y operación;
  - PLAN y WPs vigentes;
  - decisiones actuales;
  - gobernanza;
  - comentarios y docstrings;
  - nombres/metadata actuales en Control;
  - ejemplos y mensajes de tooling.
- Renombrar archivos canónicos cuyo propio nombre contenga el legado, por ejemplo la decisión de coordinación con Control.
- Mantener referencias históricas sólo donde reescribirlas rompería trazabilidad o inmutabilidad.

### 5. Evidencia histórica e inmutabilidad

No reescribir:

- historia Git existente;
- mensajes de commits ya creados;
- títulos/URLs históricos de PRs;
- nombres de ramas ya integradas/borradas;
- handoffs inmutables de Control publicados en iteraciones previas;
- hashes/evidencias cuya validez dependa del contenido exacto.

Crear una nota canónica de migración que explique que `Botonera2` y `Botonera2-Control` son nombres históricos anteriores de `SIS-Leg` y `SIS-Leg-Control`, para interpretar evidencia vieja sin ambigüedad.

## Criterios de aceptación

- Los dos repositorios existen con los nombres `SIS-Leg` y `SIS-Leg-Control`.
- Los remotos locales utilizados por coordinación apuntan a los nombres nuevos.
- Ningún documento canónico vigente identifica al proyecto como Botonera2.
- Ningún comentario/docstring vigente usa el nombre legado salvo cita histórica justificada.
- No quedan imports `botonera2_backend` ni `botonera2_device_bridge`.
- No quedan paquetes `@botonera2/*`.
- No quedan servicios/rutas operativas activas bajo `/opt/botonera2` o unidades `botonera2-*.service`.
- No quedan variables de entorno `BOTONERA2_*` en configuración activa.
- El protocolo Control y sus consumidores funcionan con los nombres/campos nuevos.
- CI completa pasa después del rename de identificadores internos.
- Empaquetado de producción funciona.
- Instalación/migración desde una instalación existente queda documentada y probada en entorno controlado.
- La configuración runtime local se conserva byte-a-byte cuando corresponda.
- GitHub Actions y notificaciones siguen funcionando bajo los repositorios nuevos.
- Los links/remotos nuevos son canónicos; redirects de GitHub no son dependencia operacional.
- Existe nota de legado para interpretar evidencia histórica inmutable.
- El logo humano aprobado no fue modificado.
