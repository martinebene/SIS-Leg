# WP-098 - Fuente única de fotos de concejales en configuración

## Estado documental

`APROBADO / CAMPAÑA FIELD_ADJUSTMENTS_2026_09_10`

## Origen

Surge de la validación humana de campo del 10/09/2026. El padrón ya define `ruta_imagen`, pero hoy existen copias repetidas de las fotos dentro de assets de distintas superficies. La campaña exige que exista una única fuente física de imágenes bajo configuración local y que todas las interfaces consuman esa misma fuente.

## Objetivo

Unificar las fotos de concejales en un único recurso runtime bajo `config/`, eliminando copias funcionales por aplicación y permitiendo que una sustitución de imagen en la configuración local se refleje en todas las superficies sin reconstruir el frontend.

## Alcance obligatorio

- Definir una única ubicación física runtime bajo `config/`, preferentemente `config/assets/bancas/` o equivalente técnicamente justificado.
- Mantener `config/concejales.csv` como fuente de la referencia `ruta_imagen`.
- Hacer que todas las superficies que muestran fotos de concejales resuelvan la imagen desde esa fuente única.
- Eliminar la necesidad de mantener copias equivalentes de las mismas fotos dentro de assets particulares de Recinto, Moderación u otras aplicaciones.
- Un cambio de archivo de imagen en la configuración local debe verse en todas las superficies sin rebuild del frontend.
- Las rutas declaradas deben ser relativas/internas y seguras.
- Rechazar path traversal, rutas absolutas y URL externas cuando se trate de `ruta_imagen` de concejales.
- Mantener un comportamiento explícito y seguro ante imagen inexistente o inválida, sin romper la superficie completa.
- Desarrollo y tests deben disponer de defaults/ejemplos reproducibles, sin convertir las fotos productivas locales en archivos que una actualización futura sobrescriba silenciosamente.
- Preservar el aislamiento de configuración local definido por la arquitectura actual.
- Documentar el modelo resultante para que WP-100 pueda incorporar recursos nuevos de configuración cuando falten, sin sobrescribir los existentes.

## Migración productiva

La migración de las fotos actualmente usadas en producción queda fuera de este WP. Se realizará posteriormente por operador local, después de la integración del lote de desarrollo y sólo con autorización explícita.

Este WP no debe copiar, mover, borrar ni modificar imágenes en el host productivo.

## Validación mínima

- pruebas unitarias de resolución/validación de `ruta_imagen`;
- pruebas de seguridad para path traversal, rutas absolutas y URL externas;
- pruebas de integración/frontend que demuestren que las superficies relevantes usan la misma fuente runtime;
- prueba que demuestre que sustituir el recurso configurado no requiere rebuild de frontend;
- verificación de fallback ante recurso ausente o inválido;
- `pnpm format:check`, lint, typecheck y checks de contrato aplicables;
- suite backend aplicable;
- Playwright/E2E cuando corresponda para verificar renderizado en las superficies afectadas;
- `git diff --check`;
- CI candidata completa.

## Fuera de alcance

- Migrar físicamente las fotos de producción.
- Tocar producción, servicios, wrappers, `.desktop` o configuración productiva.
- Implementar la pantalla Zócalo de WP-099.
- Rediseñar el actualizador de WP-100.
- Modificar reglas de negocio, padrón o identidad institucional salvo lo estrictamente necesario para resolver la fuente de imágenes.

## Relación con la campaña

WP-098 sigue a WP-097 ya integrado. Su modelo de recursos de configuración debe quedar estabilizado antes de WP-099 y especialmente antes de WP-100, que deberá preservar configuración local e incorporar recursos nuevos sólo cuando todavía no existan.
