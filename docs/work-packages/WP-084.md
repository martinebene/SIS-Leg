# WP-084 - Generalizar identidad institucional y hacer configurable el cuerpo legislativo

## Estado documental

`INTEGRADO`

## Objetivo

Eliminar el acoplamiento activo de SIS-Leg al Concejo Deliberante de Puerto Madryn, incorporando un nombre institucional configurable y generalizando documentación/comentarios activos para que el mismo sistema pueda instalarse en otros concejos deliberantes o legislaturas.

## Resultado esperado

La cabecera de Recinto toma el nombre del cuerpo legislativo desde `system.toml`; código y documentación activa no dependen de Puerto Madryn ni de autoridades personales/locales hardcodeadas. La historia del proyecto permanece intacta.

## Dependencias

- WP-079 `INTEGRADO`: auditoría de identidad/historia reproducible.
- WP-077 `INTEGRADO`: identidad oficial SIS-Leg y separación de referencias activas/históricas.

## Fuentes canónicas obligatorias

- `config/system.example.toml`.
- Modelos/cargador de configuración.
- Proyecciones/contratos backend.
- `apps/recinto/app/components/CabeceraRecinto.vue`.
- `README.md`, `AGENTS.md`, `docs/00-principios-y-alcance.md` y documentación activa.
- `manual/index.html`.
- Tests de configuración, contrato, cabecera e identidad.

## Alcance

- Agregar sección/campo institucional explícito en `system.toml`, con nombre no vacío del cuerpo legislativo.
- Valor operativo real configurable; plantilla versionada debe usar ejemplo genérico/no personal.
- Proyectar el nombre hasta Recinto y reemplazar el h1 hardcodeado.
- Buscar sistemáticamente referencias activas a `Puerto Madryn`, `Madryn`, `Concejo Deliberante de Puerto Madryn`, autoridades locales/personales y usos genéricos de `Concejo Deliberante`.
- En documentación genérica, preferir `cuerpo legislativo` cuando se describa la institución abstracta.
- Conservar términos de dominio útiles como `concejal`, `concejales.csv` y DTOs existentes salvo que una referencia concreta impida configurabilidad.
- Clasificar y preservar historia/decisiones que legítimamente documenten el origen local.

## Fuera de alcance

- Renombrar masivamente tipos `Concejal*`, contratos o archivos por neutralidad terminológica.
- Parametrizar todos los nombres de roles políticos si no están hardcodeados a una persona/localidad.
- Reescribir Git history, WPs cerrados o handoffs inmutables.
- Cambiar branding SIS-Leg.

## Componentes previsiblemente afectados

- Configuración backend.
- Proyección/serialización/cliente.
- Cabecera Recinto.
- Plantillas/config README.
- Documentación activa y manual.
- Tests anti-hardcode.

## Criterios de aceptación

1. `system.toml` exige un nombre institucional no vacío.
2. Recinto muestra exactamente el nombre configurado.
3. Tests validan al menos dos nombres de distinta longitud sin romper cabecera a 1366×768 y 1920×1080.
4. Búsqueda automatizada/manual no encuentra referencias activas específicas a Puerto Madryn fuera de contextos históricos/ejemplos expresamente permitidos.
5. No hay autoridades personales/locales hardcodeadas en código/config activa.
6. Documentación general habla de `cuerpo legislativo` cuando no se refiere a una institución concreta.
7. Contratos internos de `Concejal` no se renombran sin necesidad.

## Pruebas obligatorias

- Tests de carga/validación `system.toml`.
- Contrato/proyección/cliente.
- Cabecera Recinto.
- Playwright/geometría con nombres corto/largo.
- Auditoría de referencias institucionales activas.
- Suite estática/build aplicable.
- `git diff --check`.

## Invariantes y restricciones

- Configuración se congela conforme contrato actual.
- No inventar una taxonomía legislativa universal.
- Preservar historia.
- No rebase/force-push.
