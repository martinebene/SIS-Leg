# WP-079 - Restablecer el gate de identidad histórica sin borrar evidencia legítima

## Estado documental

`INTEGRADO`

## Objetivo

Restablecer la reproducibilidad del gate de identidad legada sobre el HEAD vigente de SIS-Leg, diferenciando referencias activas prohibidas de referencias históricas legítimas creadas por el corte WP-077 y por su trazabilidad posterior.

## Resultado esperado

La auditoría de identidad vuelve a pasar sobre `main` sin eliminar ni reescribir historia. Una referencia activa nueva al nombre/ruta legada continúa fallando, mientras la evidencia histórica permitida queda clasificada por una política explícita, acotada y testeada.

## Dependencias

- WP-077 `INTEGRADO`: corte de identidad SIS-Leg y auditoría de referencias legadas que origina el contrato actual.

## Fuentes canónicas obligatorias

- `AGENTS.md`.
- `scripts/auditar_identidad_legada.py`.
- `tests/test_auditoria_identidad_legada.py`.
- `docs/work-packages/WP-077.md`.
- `docs/implementation/PLAN.md`.
- `SIS-Leg-Control/campaigns/2026-09-06-human-test-round-5/astra-audit/TRIAGE_ORCHESTRATOR.md`, ASTRA-010.
- DEC-001, DEC-003, DEC-007, DEC-017, DEC-019.

## Alcance

- Reproducir el fallo de ASTRA-010 sobre el HEAD vigente.
- Revisar la política/allowlist del auditor y distinguir rutas/contenidos históricos permitidos de referencias activas.
- Incorporar explícitamente `PLAN.md` y cualquier otra fuente documental histórica legítima necesaria sin crear una excepción global.
- Agregar tests positivos y negativos que demuestren la diferencia entre historia permitida y referencia activa nueva.
- Mantener mensajes de error suficientemente diagnósticos para CI.

## Fuera de alcance

- Borrar, editar o reescribir WPs, PLAN, commits, handoffs o evidencia histórica únicamente para eliminar palabras legadas.
- Relajar la auditoría hasta aceptar referencias activas.
- Cambiar identidad oficial, repositorios, rutas runtime o despliegue.
- Resolver otros hallazgos Astra.

## Componentes previsiblemente afectados

- `scripts/auditar_identidad_legada.py`.
- `tests/test_auditoria_identidad_legada.py`.
- Documentación estrictamente necesaria para explicar la política.

## Criterios de aceptación

1. La auditoría de identidad pasa sobre el HEAD candidato completo.
2. Las referencias históricas legítimas ya existentes quedan admitidas mediante criterio explícito y trazable, no por exclusión amplia de directorios completos salvo justificación demostrada.
3. Una referencia activa nueva a `Botonera2`, rutas antiguas o identidad técnica legada en código/configuración activa hace fallar la prueba.
4. Un cambio documental futuro que copie accidentalmente una referencia activa fuera de los contextos históricos permitidos sigue siendo detectable.
5. No se modifica ni elimina evidencia histórica para obtener verde.
6. El comportamiento queda cubierto por tests deterministas.

## Pruebas obligatorias

- `uv run pytest tests/test_auditoria_identidad_legada.py`.
- Ejecución directa del auditor sobre el checkout candidato.
- `uv run ruff check .`.
- `uv run ruff format --check .`.
- `uv run pyright`.
- `git diff --check`.
- CI completa de PR conforme DEC-019.

## Invariantes y restricciones

- La historia es evidencia y no se “limpia” para satisfacer el gate.
- La allowlist debe ser mínima y justificable por contexto.
- No rebase ni force-push.
- No modificar configuración runtime local.

## Herramientas MCP y documentación técnica externa

No se prevé dependencia de documentación externa. GitHub puede utilizarse para verificar historia/rutas dentro de la autoridad vigente.
