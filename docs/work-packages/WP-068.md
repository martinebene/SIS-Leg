# WP-068 - Evitar CI completa en pushes documentales a main

## Estado documental

`INTEGRADO`

## Objetivo

Ajustar el trigger de GitHub Actions para que los commits puramente documentales sobre `main` no ejecuten la batería completa de CI, manteniendo intacta la CI completa de todas las Pull Requests y de cualquier push material a `main`.

## Resultado esperado

Activaciones, cierres y mantenimiento documental directo realizados bajo DEC-005 dejan de disparar backend, frontend, E2E, build y empaquetado cuando no cambió ningún archivo ejecutable/material.

## Dependencias

- DEC-019 aprobada por HUMAN_GATE.

## Decisiones humanas cerradas

1. Las Pull Requests siguen ejecutando CI completa sin filtros por rutas.
2. Los pushes a `main` ejecutan CI completa si contienen al menos un archivo no documental.
3. Un push a `main` compuesto exclusivamente por `docs/**` y/o archivos `*.md` no dispara CI de Product.
4. No se reducen los ocho jobs existentes para eventos elegibles.
5. No se agrega una dependencia externa sólo para clasificar rutas.
6. El cierre documental posterior a este WP servirá como prueba operativa de que no aparece una nueva run.

## Criterios de aceptación

1. `pull_request` conserva CI completa sin `paths-ignore`.
2. `push.branches: [main]` conserva su filtro de rama y agrega exclusión documental.
3. `docs/**` y `**/*.md` quedan ignorados únicamente para `push` a `main`.
4. Un cambio de `.github/workflows/ci.yml` continúa siendo elegible para CI completa.
5. Un commit mixto documentación + cualquier ruta material continúa siendo elegible para CI completa.
6. Ninguno de los ocho jobs existentes cambia su contenido o condición de ejecución.
7. La PR de WP-068 ejecuta y supera la CI completa.
8. El merge de WP-068 a `main` ejecuta y supera CI completa.
9. El posterior commit documental de cierre de WP-068 no crea una run de CI de Product para su SHA.

## Pruebas obligatorias

- Validación sintáctica/estructural razonable del YAML.
- Diff explícito que demuestre que sólo cambia el trigger y, si corresponde, documentación.
- Contraste con documentación oficial vigente de GitHub Actions.
- CI completa de la PR exacta.
- Verificación post-merge por ORCHESTRATOR.
- Verificación empírica del primer commit documental posterior al merge.

## Invariantes y restricciones

- No rebase ni force-push.
- Squash merge.
- Revisión independiente obligatoria.
- No relajar tests para conseguir verde.
- WP-029 permanece BLOQUEADO.
- WP-066 queda operacionalmente en pausa hasta integrar WP-068, para que su flujo ya use la política nueva.
